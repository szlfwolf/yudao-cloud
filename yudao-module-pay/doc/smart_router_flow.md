# 一、整体时序图（主干流程）

> 场景：**一次正常支付成功，统计反哺路由**

```
下游商户
   |
   | 1. 创建支付订单
   |
API 网关
   |
   | 2. 请求路由
   |
智能路由引擎
   |
   | 3. 拉取路由快照（Redis）
   |
Redis（路由快照）
   |
   | 4. 返回各渠道健康度
   |
智能路由引擎
   |
   | 5. 规则过滤 + 打分 + 加权随机
   |
   | 6. 选定渠道（WECHAT_02）
   |
   |---- 异步 ----> 路由决策日志（MQ / ES）
   |
支付核心服务
   |
   | 7. 调用上游支付接口
   |
上游支付渠道
   |
   | 8. 返回二维码 / 支付中
   |
用户扫码支付
   |
上游支付渠道
   |
   | 9. 支付成功回调
   |
支付核心服务
   |
   | 10. 订单状态 → SUCCESS
   |
   | 11. 发 PAY_SUCCESS 事件
   |
MQ（统计事件）
   |
   | 12. 消费统计事件
   |
统计服务
   |
   | 13. 更新 Redis 实时统计
   | 14. 更新 MySQL 日汇总
   |
   | 15. 计算新的渠道健康度
   |

   |
   | 16. 覆盖 WECHAT_02 最新快照
   |

   |
   | 17. 定时拉取新快照（1~5s）
   |
   | —— 下一单开始使用新数据 ——
```

# 二、关键节点逐点拆解（为什么这么设计）

---

## 1️⃣ 路由只用「快照数据」，不直接用实时统计

### 原因

* 防止同一请求过程中数据抖动
* 避免 Redis 多 Key 频繁访问
* 提升一致性 & 性能

### 快照示例

```json
route:snapshot:WECHAT_02
{
  "health_score": 0.87,
  "success_rate_5m": 0.96,
  "avg_latency": 420,
  "circuit_break": false
}
```

---

## 2️⃣ 路由决策日志是“旁路”，绝不阻塞下单

```
路由完成
 → fire-and-forget 写 MQ
```

用途：

* 事后解释：**为什么给这个商户选了这个渠道**
* 故障复盘
* 算法调参

---

## 3️⃣ 统计事件只在「订单终态」触发

### 状态机约束

```
INIT → PAYING → SUCCESS  ✅ 触发
INIT → PAYING → FAIL     ✅ 触发
```

❌ PAYING / 重复回调 / 中间态不触发

👉 **避免重复统计 & 口径混乱**

---

## 4️⃣ 统计服务是闭环的“发动机”

统计服务一口气做 3 件事：

1. **Redis 实时指标**
2. **MySQL / OLAP 汇总**
3. **重新计算路由健康度**

> 路由算法 ≠ 自己算自己
> **由统计系统“反向喂”路由**

---

## 5️⃣ 路由快照更新 ≠ 每一笔交易更新

### 更新策略（非常重要）

| 项目       | 建议      |
| -------- | ------- |
| 统计窗口     | 1m / 5m |
| 快照刷新     | 1～5 秒   |
| score 变化 | ≤ ±5%   |

👉 防止**自激振荡**

# 三、异常场景时序（你一定会遇到）

---

## 场景 A：某渠道突然大面积失败（熔断）

```
统计服务
   |
   | 1. 1分钟失败率 > 30%
   |
   | 2. 设置 circuit_break = true
   |
Redis（路由快照）
   |
智能路由引擎
   |
   | 3. 下次路由直接过滤该渠道
```

**无需人工介入，自动止血**

---

## 场景 B：熔断后恢复（半开）

```
定时任务
   |
   | 1. 熔断 60s 到期
   |
   | 2. 开放 10% 流量
   |
   | 3. 观察成功率
```

成功 → 正常
失败 → 再次熔断

---

## 场景 C：统计系统短暂不可用

```
路由引擎
   |
   | 使用上一次快照
   |
   | 兜底到默认渠道
```

👉 **交易不中断，智能暂时降级**

# 四、闭环设计中最容易踩的 5 个坑（重点）

1️⃣ 路由直接查交易表
2️⃣ 路由实时用统计 Key，不做快照
3️⃣ 成功率波动直接影响 100% 流量
4️⃣ 新渠道一上线就全量放
5️⃣ 没有路由决策日志（出了问题解释不了）

你现在这套设计 **全部避开了**
